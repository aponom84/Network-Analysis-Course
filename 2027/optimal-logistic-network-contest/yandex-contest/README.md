# Пакет задачи для Яндекс.Контеста (формат Polygon)

## Как устроена задача

Тип задачи — обычный **PROBLEM_WITH_CHECKER**, 50 тестов: тест $i$ — сеть $i$ из `reference_values.csv`. Программа участника получает сеть на stdin и печатает решение в CSV. Заранее посчитанные решения участник сдаёт одной программой на Python 3, которую собирает [`../pack_submission.py`](../pack_submission.py): решения сжаты и встроены в код (все 50 решений GVNS занимают около 1 МБ).

Чекер [`check.cpp`](./check.cpp) (testlib) проверяет допустимость и ставит за тест $100\,w_i\,B_i/\mathrm{cost}_i$ баллов через `quitp`, где $w_i = 1/(3\,|\text{группа}|)$. Сумма по тестам равна $100\,S$, поэтому постпроцессор не нужен: лидерборд SCORING сортирует участников прямо по $S$. Недопустимое решение получает вердикт OK и 0 баллов (причина видна в комментарии к тесту), поэтому тестирование не останавливается.

## Сборка

```bash
../fetch_data.sh                                   # корпус в ../data
python make_package.py --main-solutions <каталог>  # <каталог>/<имя сети>.csv — главное решение
```

Получаются два архива по 2,3 МБ:

- `build/logistic-net-2027-contest.zip` — пакет **соревнования**: `contest.xml` и задача в `problems/logistic-net-2027/` (так устроены пакеты, которые выгружает Polygon);
- `build/logistic-net-2027-problem.zip` — пакет **задачи** с тем же содержимым.

Пакет задачи содержит `problem.xml`, 50 тестов с ответами `NN.a` («бейзлайн вес»), чекер, testlib, условие (`statements/russian/problem.tex`, `statements/.html/russian/problem.html`, `statement-sections/`), главное решение `solutions/main.py`. Главное решение — упакованные решения GVNS из репозитория статьи: в нём нет решений для `150_nodes_2` и `150_nodes_3`, поэтому оно набирает $100\,S = 88{,}19$.

Проверено локально: все 50 тестов (главное решение → чекер) проходят за 0,2–0,3 с на тест, сумма баллов чекера совпадает с `score.py`; пустой вывод, мусор, несуществующий склад, неверный объём и превышение $W_v$ дают 0 баллов с понятной причиной.

## Загрузка в Контест

1. **Соревнования → Загрузить соревнование**, формат **POLYGON**, файл `build/logistic-net-2027-contest.zip`. Пакет задачи (`-problem.zip`) в это окно не подходит: соревнованию нужен `contest.xml`.
   - Если импорт соревнования снова завершится ошибкой: создать соревнование вручную, а задачу загрузить из `build/logistic-net-2027-problem.zip` (**Задачи → импорт из Polygon**) и добавить в соревнование.
   - Надёжный запасной путь: создать задачу в Polygon (тесты, `check.cpp` и условие взять из `build/contest/problems/logistic-net-2027/`), собрать там пакет и импортировать задачу в Контест по ссылке Polygon.
   - Адреса в `contest.xml` и `problem.xml` условные (`polygon.codeforces.com/p0000000/...`), потому что пакет собран не в Polygon. Если Контест проверяет их, это первая причина ошибки.
2. **Настройки чекера** задачи: тип **TESTLIB_EXITCODE_CHECKER**, **Чекер выставляет баллы — да**. Проверить, что чекер скомпилировался из `check.cpp` вместе с `testlib.h`.
3. **Настройки файлов**: чтение из stdin и запись в stdout разрешены; **ограничение размера исходного кода — 5 МБ** (посылка с 50 решениями около 1 МБ).
4. **Ограничения на запуск**: 10 с и 512 МБ (заданы в `problem.xml`; проверить после импорта).
5. **Тесты**: один набор из 50 тестов без примеров; тестирование не прерывается на первом неуспешном тесте.
6. **Соревнование**: лидерборд **SCORING**, **посылка для зачёта — лучшая по результату**, без штрафа за попытки; компилятор **Python 3** (остальные можно оставить: участник вправе сдать и сам алгоритм, если он укладывается в 10 с на сеть).
7. Отправить `problems/logistic-net-2027/solutions/main.py` от имени организатора и убедиться, что набрано 88,19 балла.

Итоговая оценка в накопленную ставится по лидерборду: сумма баллов $> 100$ означает, что бейзлайн преодолён (см. раздел 9 регламента).
